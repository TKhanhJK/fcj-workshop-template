AWS VPC: Public Subnet, Private Subnet and Internet Gateway

Understanding the fundamentals of Amazon VPC, subnet segmentation, routing behaviors, and how resources securely connect to the Internet.

1. Introduction

In cloud architecture, network isolation and traffic control represent the foundational line of defense. Amazon Virtual Private Cloud (Amazon VPC) is the core networking foundation of AWS. It allows you to provision a logically isolated section of the AWS Cloud where you can launch AWS resources in a virtual network that you define.

Without a firm grasp of VPC constructs—specifically subnets, route tables, and gateways—securing workloads, preventing unauthorized ingress, and designing scalable multi-tier architectures becomes nearly impossible.

2. Key Points to Know

Before designing networks, engineers must be familiar with eight fundamental networking primitives:

Amazon VPC
Your dedicated, logically isolated virtual network across an AWS Region.
CIDR Block
Classless Inter-Domain Routing range defining the total IP address pool (e.g., 10.0.0.0/16).
Subnet
A contiguous range of IP addresses within a VPC, tied to a single Availability Zone.
Public Subnet
A subnet whose route table directs default Internet traffic (0.0.0.0/0) to an Internet Gateway.
Private Subnet
A subnet with no direct route to an Internet Gateway; isolates internal databases/services.
Internet Gateway (IGW)
A horizontally scaled, redundant VPC component facilitating direct IPv4/IPv6 Internet communication.
Route Table
A set of rules (routes) that determines where network traffic from subnets or gateways is directed.
Availability Zone (AZ)
One or more discrete data centers with redundant power and networking in an AWS Region.

3. What is Amazon VPC?

Simply put, an Amazon VPC is your own private datacenter inside AWS. When you create a VPC, you assign a primary IPv4 CIDR block (ranging from /16 to /28).

Technically, AWS manages the underlying SDN (Software-Defined Networking). All communication within the VPC CIDR uses an implicit local route that cannot be deleted. You have complete control over IP address selection, subnet creation, routing tables, and network security gateways.

4. Public Subnet vs Private Subnet

The distinction between a public and private subnet is determined solely by its Route Table association:

Feature Public Subnet Private Subnet
Internet Connectivity Direct bidirectional access to the Internet. No direct inbound or outbound Internet route.
Route Table Rule Contains route: 0.0.0.0/0 → igw-xxxx Only local route or route to a NAT Gateway / VPC Endpoint.
IP Addressing Instances require both a Private IP and a Public / Elastic IP. Instances only possess Private IPs from the subnet CIDR.
Typical Resources Load Balancers (ALB), Bastion Hosts, Public Web Servers. Databases (RDS), Backend APIs, Microservices, Caching (ElastiCache).
Security Purpose Accept incoming external client traffic; public entry point. Eliminates direct Internet attack surface for sensitive assets.

5. Internet Gateway (IGW)

An Internet Gateway (IGW) serves two purposes: providing a target in your VPC route tables for Internet-routable traffic, and performing Network Address Translation (NAT) for instances assigned public IPv4 addresses.

It is fully managed by AWS, highly available, and horizontally scalable with no bandwidth bottlenecks.

6. How Does an EC2 Instance in a Public Subnet Access the Internet?

Launching an EC2 instance into a public subnet is not enough on its own. For an EC2 instance to successfully send and receive packets to and from the Internet, all five conditions must be satisfied:

  1. VPC Attachment: The VPC must have an Internet Gateway created and attached to it.
  2. Subnet Routing: The subnet's Route Table must explicitly declare a default route: 0.0.0.0/0 pointing to the Internet Gateway ID (igw-xxxx).
  3. Public IP Address: The EC2 instance must have an Auto-assigned Public IPv4 address or an Elastic IP (EIP) mapped to its private IP.
  4. Security Group Rules: The instance's Security Group must allow outbound traffic on desired ports (default is all outbound allowed) and appropriate inbound traffic.
  5. Network ACL Rules: Both Inbound and Outbound Network ACLs associated with the subnet must allow the corresponding traffic and ephemeral return ports (1024–65535).

7. Why Use Private Subnets?

Exposing databases, message queues, or internal backend services directly to the public Internet creates an unnecessary attack vector. By positioning these workloads in a Private Subnet, they cannot be addressed directly from the Internet because they lack public IPs and route table paths to an IGW.

In a classic multi-tier architecture, public subnets act as an ingress gatekeeper (hosting reverse proxies or Application Load Balancers), which forward filtered requests down to private backend tiers:

9. Practical Example: Secure 2-Tier Web Application

Consider a standard web application where end-users browse products and submit orders:

  • Public Tier: An EC2 instance running Nginx resides in the Public Subnet (10.0.1.0/24). Its Security Group allows inbound HTTP (Port 80) and HTTPS (Port 443) from 0.0.0.0/0.
  • Private Tier: A PostgreSQL database on RDS resides in the Private Subnet (10.0.2.0/24). Its Security Group only allows inbound Port 5432 from the Security Group ID of the Web Server.
Why this architecture improves security:

Even if an attacker scans public IP ranges on the Internet, the database IP does not exist on the public web. Furthermore, the database refuses any connection that does not originate directly from the legitimate web application layer.

10. Key Takeaways

  • An Amazon VPC is a private, isolated network defined by CIDR blocks within an AWS Region.
  • The presence of an explicit route (0.0.0.0/0) to an Internet Gateway in the route table is what defines a subnet as public.
  • For an EC2 instance in a public subnet to communicate with the Internet, it requires a Public IP, correct Route Table, permissive Security Group rules, and non-blocking Network ACLs.
  • Private subnets protect high-value data and internal services by removing all public Internet exposure.
  • Combining public and private subnets implements the foundational principle of Defense-in-Depth.
