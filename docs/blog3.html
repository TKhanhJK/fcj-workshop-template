Security Groups vs Network ACLs

Understanding the differences between Security Groups and Network Access Control Lists (NACLs) and how they cooperate to enforce defense-in-depth across AWS networks.

1. Introduction

When securing cloud networks inside an Amazon VPC, security cannot be implemented as a single perimeter barrier. Instead, AWS employs a layered Defense-in-Depth security model.

At the core of this model are two distinct firewall mechanisms: Security Groups (SGs) and Network Access Control Lists (NACLs). While both filter inbound and outbound IP traffic, they operate at completely different network boundaries, utilize different evaluation logic, and serve complementary architectural roles.

2. Key Points to Know

Security Group
Virtual firewall operating at the Elastic Network Interface (ENI) / instance level.
Network ACL
Subnet-level boundary firewall filtering all traffic entering or leaving an entire subnet.
Stateful
Automatically remembers active connections; return response traffic is automatically allowed.
Stateless
Does not track connection state; responses must be explicitly permitted by corresponding rules.
Rule Numbers
NACL rules evaluate in ascending numerical order (e.g., 100, 200); first match applies.
Ephemeral Ports
Short-lived client ports (typically 1024–65535) required for stateless NACL return communications.

3. What is a Security Group?

A Security Group acts as a virtual firewall for your EC2 instances to control incoming and outgoing traffic. Security groups are attached to the instance's Elastic Network Interface (ENI), not the instance hardware itself or the subnet.

Key characteristics of Security Groups:

  • Stateful Filtering: If an inbound request is permitted (e.g., HTTP on port 80), the outbound response traffic is automatically allowed to return to the client, regardless of outbound security group rules.
  • Allow Rules Only: You cannot create explicit "Deny" rules. Everything is blocked by default until an explicit "Allow" rule is defined.
  • Security Group Referencing: Instead of hardcoding CIDR IP addresses, a Security Group can reference another Security Group ID as a source or destination (e.g., allowing port 3306 only from sg-web-servers).

4. What is a Network ACL?

A Network Access Control List (NACL) is an optional layer of security for your VPC that acts as a firewall for controlling traffic in and out of one or more subnets.

Key characteristics of Network ACLs:

  • Stateless Filtering: NACLs have no memory of request state. If inbound port 443 is allowed, outbound responses will be dropped unless you explicitly configure an outbound NACL rule permitting traffic to ephemeral client ports (1024–65535).
  • Allow and Deny Rules: You can explicitly write rules that Deny specific IP addresses or CIDR ranges (ideal for blocking compromised hosts or malicious scanners).
  • Numbered Evaluation: Rules are processed in ascending numerical order (e.g., rule 10 is evaluated before rule 20). As soon as a rule matches traffic, it is applied immediately without evaluating subsequent rules.

7. When to Use Each

  • Use Security Groups for standard daily security: Use SGs to restrict access to applications based on specific ports (e.g., port 443 for web, port 22 for administrative bastion access). Take advantage of security group referencing so database tiers only accept packets from authorized application server security groups.
  • Use Network ACLs for coarse-grained perimeter control: Use NACLs when you need to immediately block a known malicious IP address or subnet attacking your application (using an explicit DENY rule). NACLs are also used to satisfy compliance mandates requiring strict subnet-level isolation.

8. Security Best Practices

Key Recommendations for AWS Architects:
  • Keep NACLs simple: Overcomplicating stateless NACL rules can lead to hard-to-diagnose connectivity drops due to ephemeral port oversights. Rely on the Default NACL (allow all) unless you have explicit subnet isolation or blocking needs.
  • Strict Security Group Ingress: Never open administrative ports (SSH 22, RDP 3389) to 0.0.0.0/0. Restrict access to a corporate VPN or use AWS Systems Manager Session Manager instead.
  • Chain Security Groups: In multi-tier designs, configure backend tiers (RDS / Caches) with ingress rules referencing the Security Group of the web tier, rather than static IP CIDRs.

9. Key Takeaways

  • Security Groups are stateful and operate at the instance / ENI level with ALLOW rules only.
  • Network ACLs are stateless and operate at the subnet level with both ALLOW and DENY rules.
  • Because NACLs are stateless, return traffic requires corresponding outbound rules for ephemeral ports (1024–65535).
  • Inbound traffic is evaluated by Network ACLs first, followed by Security Groups second.
  • Together, SGs and NACLs provide a robust, layered defense protecting cloud workloads from perimeter to host.
